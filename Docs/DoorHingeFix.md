# 왼쪽 경첩 기준 문 개폐

2026-10-21 / Unity 6000.2.8f1 / Windows64 기준입니다.

## 변경 의도

이전 수정은 회전축을 월드 Y로 맞췄지만 문 중심을 그대로 회전시켰습니다. 실제 경첩 문처럼 동작하려면 **왼쪽 경첩은 고정되고 문 중심도 경첩을 따라 이동**해야 합니다.

문 프리팹 안에 `DoorHinge`라는 빈 자식 Transform을 하나 추가했습니다. 현재 공통 Door와 R01_Door 모델에서 R01 방 안쪽을 기준으로 왼쪽 가장자리인지 실제 스폰 결과로 확인했습니다. 일반적인 모델의 로컬 X/Y/Z 방향을 추측하는 코드를 게임에 넣지 않고, 프리팹의 기준점 위치로 경첩을 정합니다.

## 서로 다른 세 기준점

| 기준점 | 역할 |
|---|---|
| R01_DoorPoint 등 | 다음 방과 연결하는 문턱 중앙 기준 |
| R01_DoorModelPoint 등 | CSV가 지정한 문 프리팹을 생성하는 앵커 |
| 문 프리팹의 DoorHinge | 문짝이 회전하는 경첩 위치 |

방 연결점과 문 스폰 앵커를 경첩 위치로 옮기지 않았습니다. 새 경첩 기준점만 실제 문짝 가장자리에 둡니다. 동일한 공통 프리팹을 참조하는 CSV 문에는 같은 개폐 방식이 적용됩니다.

## 동작과 코드

`WorldDoorView.Initialize`가 닫힌 로컬 위치·회전을 저장하고 자식 `DoorHinge`가 정확히 하나인지 확인합니다. 기준점이 없거나 중복되면 오류를 표시하며 임의로 문 가운데를 사용하지 않습니다.

문 열기 허가를 받으면 다음 순서로 처리합니다.

1. 저장한 닫힌 자세에서 시작합니다.
2. 현재 부모 배치를 반영한 경첩의 월드 위치를 읽습니다.
3. 문 중심의 새 위치를 `경첩 + 월드Y회전 × (닫힌 중심 − 경첩)`으로 계산합니다.
4. 기존 월드 Y 회전 변환과 새 위치를 함께 적용합니다.
5. 문짝과 같은 계층의 Collider도 함께 움직이고 Physics 상태를 갱신합니다.

닫을 때는 저장한 위치·회전을 복원합니다. 이전 결과에 회전을 누적하지 않으므로 반복 개폐에서도 누적 오차를 줄입니다. 방 연결로 부모가 이동·회전하면 현재 부모 배치를 사용합니다. 각도는 기존 정수 밀리도 설정을 사용하며 Vector3·Quaternion은 Unity 표현 경계에만 있습니다.

| 파일 | 변경 |
|---|---|
| Interaction/WorldDoorView.cs | 경첩 검증·닫힌 위치 저장·위치/회전 동시 적용 |
| Interaction/InteractionPresentationGeometry.cs | 경첩을 중심으로 한 위치 계산 |
| Editor/InteractionPresentationChecks.cs | 양/음수 각도의 위치와 반경 검사 추가 |
| Editor/RoomPreviewChecks.cs | 경첩 고정·문 중심 이동·닫힌 위치 복원 검사 추가 |
| Assets/2.Model/Prefabs/Door.prefab | 실제 왼쪽 DoorHinge 기준점 |
| Assets/2.Model/Prefabs/R01/R01_Door.prefab | 동일한 표시 계약 적용 |

기존 문 허가 API·Protobuf·서버 판정은 그대로 사용합니다. 허가 후 열기·닫기는 로컬 처리합니다. 이번 수정 때문에 Docker 서버를 재배포할 필요는 없습니다.

## 기획·아트 작업자 규칙

- CSV에는 기존처럼 Interactable·Door 기능을 선언한 프리팹을 연결합니다.
- 해당 프리팹 아래 빈 자식 `DoorHinge`를 정확히 하나 만들고 실제 경첩 위치에 놓습니다. 모델마다 축과 피벗이 다를 수 있으므로 현재 모델의 좌표값을 다른 모델에 그대로 복사하지 않습니다.
- `DoorHinge`에는 메시나 별도 충돌체가 필요하지 않습니다. 문짝·손잡이·기존 Collider는 움직이는 문 계층에 둡니다. 고정 문틀은 그 계층에 포함하지 않습니다.
- 경첩은 선택한 플레이어 시점에 따라 좌우가 바뀌지 않는 고정된 물리 위치입니다. 반대쪽에서 보면 보이는 좌우가 달라질 수 있습니다.
- 프리팹 변경을 Git에 함께 공유합니다. CSV나 FBX 원본을 이번 작업에서 수정하지 않았습니다.

## 검증 결과

- 표현 좌표·재질 검사 **22개** 통과.
- Play 모드 방 미리보기 검사 **54개** 통과. 경첩 고정·문 중심 이동·닫힌 위치 복원을 포함합니다.
- 실제 A/B R01에서 방 출구 방향과 비교해 경첩이 방 안쪽 기준 왼쪽인지 확인했습니다.
- 실제 A/B 문에서 경첩 이동 오차 약 **0.0043mm**, 문 중심 이동 약 **1135mm**, 높이 차이 약 **0.00024mm**, 닫힌 위치 복원 오차 **0mm**를 확인했습니다. 소수 오차는 Unity 부동소수점 표현 경계의 측정값입니다.

## 수정본 빌드

Windows64 Stable 클린 빌드가 성공했습니다. **`build/Stable-LeftHingeFix/`** 폴더 전체를 사용합니다. 크기는 약 **2.16GB**, 빌드 오류 0개입니다. Unity 서비스 연결·심볼 업로드 관련 경고 2개는 기존과 같습니다. 앞서 만든 Stable-InteractionPoseFix와 Stable-TextureCompressed에는 이번 경첩 수정이 들어 있지 않습니다.

이 빌드의 실제 두 PC 온라인 테스트는 사용자 테스트 항목입니다.

## 테스트 방법

1. 기존 Room Clear Test 미리보기를 종료하고 새로 시작하거나 Play를 재시작합니다. 이미 생성된 예전 문에는 새 프리팹 자식이 소급 추가되지 않습니다.
2. 플레이어를 생성하고 방 안쪽에서 문을 바라봅니다.
3. 좌클릭해 열고 닫습니다. 왼쪽 경첩이 문틀 옆에서 움직이지 않고 문짝과 Collider가 함께 회전하는지 확인합니다.
4. 문을 통과하고 여러 번 개폐한 뒤 닫힌 위치가 원래 문틀에 맞는지 확인합니다.
5. 다른 방이나 새 문 프리팹도 각 방의 실제 앞면·경첩·통로를 따로 확인합니다.
