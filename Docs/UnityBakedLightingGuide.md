# 현재 방 구조의 조명 제작·베이크 사용법

> 문서 대조일: **2026-10-26**. 현재 코드·설정을 기준으로 설명을 점검했습니다. 본문의 과거 검사 수치·실행 기록은 해당 날짜의 결과입니다. [현재 상태·문서 검토 범위](문서_현행화_점검표.md)를 함께 확인합니다.

## 1. 현재 선택한 방식

기존 Join/Ingame과 역할별 누적 방 스폰을 유지합니다. 별도 게임 씬이나 ROOM_LIGHT_SPAWNTABLE을 사용하지 않고 기존 ANCHOR_NONINTERACT → PREFAB으로 조명을 배치합니다. 편집기에서 A/B 최종 배치를 구성해 **기존 라이트 프로브**에 굽고, 실행 시 역할별 결과를 복제·연결합니다.

이 문서는 초기 라이트맵 조사 대신 현재 제작 원칙을 설명합니다. 정확한 메뉴·결과·수명은 [프로브 작업 가이드](RoomProbeLighting.md)를 따릅니다.

## 2. 작업자가 조정하는 것

| 항목 | 조정 위치 | 반영 |
|---|---|---|
| 어느 방에 어떤 광원인가 | 기존 앵커 행의 역할·RoomNo·PrefabID·AnchorID | 콘텐츠 참조 갱신 후 해당 역할 재베이크 |
| 실제 위치·방향 | 작업자가 배치한 방 프리팹의 앵커 | 임의 방 안 좌표로 보정하지 않음 |
| 색·강도·범위·종류 | 조명 프리팹의 Light | 현재 Baked 모드 유지 후 재베이크 |
| 역할별 결과 | Resources/RoomProbeLighting.asset | A/B 프로브 참조 |
| 구운 결과 | Resources/RoomProbes_A.asset, RoomProbes_B.asset | .meta와 함께 공유 |

현재 조명 프리팹은 1번 Spot, 2~7번 Point입니다. Point/Spot은 모양이고 Baked는 계산 방식입니다. 실시간 광원으로 자동 바꾸는 기능은 없습니다.

## 3. 실제 제작 순서

1. Play를 종료하고 열린 씬을 저장합니다.
2. Tools → Game → Rebuild Content References로 활성 CSV와 자원 연결을 갱신합니다.
3. Tools → Game → 조명 프로브 → A 배치 준비를 실행합니다.
4. 기존 CSV·프리팹을 사용한 임시 편집 배치를 확인합니다. 앵커 좌표를 자동 변경하지 않습니다.
5. 현재 배치 베이크·저장을 실행하고 원래 씬으로 복귀합니다.
6. B도 배치 준비 → 베이크·저장을 수행합니다.
7. 저장된 결과 검사 후 Join의 로컬 A/B로 확인합니다.
8. 앵커·배치·모델·광원 값을 바꾸면 다시 베이크하고 기존 stable 폴더에 빌드합니다.

임시 씬은 제작 도구가 관리하며 빌드 씬에 추가하지 않습니다. 임시 배치에서 바꾼 값을 원본 프리팹에 자동 저장하지 않으므로 지속 변경은 원본에 적용합니다.

## 4. 화면 품질과 비용의 경계

프로브는 위치별 빛을 부드럽게 근사하므로 정교한 벽 그림자·선명한 전등 무늬를 라이트맵처럼 표현하지 않습니다. 큰 메시의 수신 위치에 따라 균일하게 보일 수 있습니다. 이번 선택은 조명 위치와 분위기가 중심인 현재 요구에 맞춘 것입니다.

실행 중 다시 베이크하지 않고 역할별 복제본 하나를 사용합니다. 새 방은 수신 설정만 적용합니다. 결과가 있는 역할에서는 기존 방향광을 끄고, 결과가 없으면 경고하며 기존 조명을 유지합니다.

## 5. 라이트맵·다른 방식과 구분

현재 런타임에는 프리팹별 라이트맵 텍스처·lightmapIndex·lightmapScaleOffset을 병합·복원하는 시스템이 없습니다. 일반 Generate Lighting만 눌러 그 기능이 생기는 것은 아닙니다. APV 전환도 현재 작업 범위가 아닙니다.

월드 조명은 프로브를 사용하지만 CloseupPreview는 별도 카메라·텍스처와 PreviewLight를 사용합니다. 따라서 게임 전체 실시간 Light가 완전히 제거됐다고 설명하지 않습니다. 미리보기 조명 대체는 별도 품질·렌더링 검사 후 변경할 항목입니다.

## 6. 수명·빌드·확인

프로브 어댑터는 전역 상태의 이전 값과 복제본을 소유하며, 자신이 현재 소유자일 때만 복원합니다. 원본 에셋을 실행 중 수정하지 않습니다. MeshRenderer.receiveGI는 편집기 조건에서만 접근하고 플레이어는 Renderer.lightProbeUsage로 보간을 사용합니다.

기존 2026-10-23 검사 기록의 A 453개·B 432개는 당시 베이크 결과입니다. 이번 문서 검토에서 새 베이크·유니티 실행·밝기 품질 확정·새 빌드를 수행한 것은 아닙니다. 방 왕복·모델 수신·배경음은 각각 확인합니다. 소리의 3초 전환이 조명을 켜고 끄는 기준은 아닙니다.
